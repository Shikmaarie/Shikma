# רחלי חדד — אתר ראשי + חנות

אתר תדמית וחנות איקומרס לרחלי חדד, מנטורית לעסקים וכסף.
Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4, ו-Three.js
לאנימציית ההירו התלת-ממדית. סליקה דרך **קארדקום**.

---

## הפעלה מקומית

```bash
npm install
cp .env.example .env.local   # ומלאו את הערכים
npm run dev                  # http://localhost:3000
```

בנייה לפרודקשן:

```bash
npm run build && npm start
```

## משתני סביבה

| משתנה | תיאור |
| --- | --- |
| `CARDCOM_TERMINAL` | מספר המסוף מהמערכת של קארדקום |
| `CARDCOM_API_NAME` | שם משתמש ה-API מקארדקום |
| `NEXT_PUBLIC_SITE_URL` | הכתובת שממנה הבילד מוגש בפועל |

`NEXT_PUBLIC_SITE_URL` נצרב ב-**זמן בנייה**, לא בזמן ריצה. להגדיר אותו לפני
`next build`, אחרת הערך הישן נשאר בבאנדל.

**הוא גם מה שקובע אם מנועי חיפוש מאנדקסים.** הדומיין החי בלבד מאונדקס; כל
כתובת אחרת — תצוגה מקדימה על `*.vercel.app` או `*.netlify.app` — מקבלת
`Disallow: /` ו-`noindex`. בלי זה עותק מלא של האתר מתחרה בדומיין של רחלי על
השם שלה. הלוגיקה ב-`src/lib/site-url.ts`.

את הערכים האמיתיים מגדירים בשרת/בפאנל האחסון — **לא** בקוד ולא ב-git.
ללא הגדרתם האתר עולה כרגיל, ורק כפתור התשלום מחזיר שגיאה מנומסת.

### עריכת תוכן

כל הטקסטים והמחירים יושבים ב-`src/data/`. לשינוי מחיר, שם תוכנית או
טקסט בעמוד הבית — עורכים שם בלבד, בלי לגעת ברכיבים.

### שלושת מצבי המוצר

לכל מוצר ב-`products.ts` יש `mode` שקובע איך רוכשים אותו:

| mode | התנהגות |
| --- | --- |
| `purchase` | יש מחיר מפורסם — נכנס לעגלה ועובר לסליקת קארדקום |
| `application` | ליווי במחיר לא מפורסם — הכפתור מוביל לשיחת התאמה, לא לעגלה |
| `free` | מדריך או הדרכה חינמית — הרשמה בלבד, לעולם לא נכנס לעגלה |

כרגע כל תוכניות הליווי הגדולות מוגדרות `application`, כי לא פורסם להן מחיר.
**כדי להפוך תוכנית למכירה ישירה** מוסיפים לה `price` ומשנים את ה-`mode`
ל-`purchase` — שאר האתר מתעדכן לבד. גם השרת אוכף את זה: ניסיון לשלוח מוצר
שאינו `purchase` לסליקה נדחה.

## תהליך התשלום

1. הלקוחה מוסיפה מוצרים לעגלה (נשמרת ב-`localStorage`).
2. בטופס התשלום נשלחים לשרת רק **מזהי המוצרים והכמויות**.
3. השרת מתמחר מחדש כל שורה מהקטלוג — **סכום שנשלח מהדפדפן לא נלקח בחשבון**,
   כך שלא ניתן לשנות מחיר מצד הלקוח.
4. השרת פותח עסקת LowProfile מול קארדקום ומחזיר כתובת לעמוד הסליקה.
5. קארדקום מחזירה את הלקוחה ל-`/checkout/success` או `/checkout/failed`,
   ובמקביל קוראת לשרת ל-`/api/cardcom/webhook`.
6. ה-webhook **מאמת מול קארדקום** את מצב העסקה לפני שהוא מסמן אותה כשולמה,
   כך שקריאה מזויפת לא יכולה לאשר הזמנה.

## עיצוב: מערכת הרצועות

האתר בנוי כערימה של **רצועות** (bands) — כל סקשן הוא פס רוחב מלא בצבע
אחד, וצבעי הטקסט שבתוכו נגזרים מהרצועה ולא מקודדים קשיח ברכיב.

כל רצועה מצהירה על עצמה עם `data-surface`:

| ערך | הקרקע | איפה |
| --- | --- | --- |
| `dark` | טורקיז עמוק / לילה | הירו, פס הקרדנציאלס, כרטיס הציטוט, פודקאסט, סיום, פוטר |
| `light` | שנהב / צדף / מנטה בהירה | מסלולים, סיפור, המלצות, שאלות ותשובות, חנות, צ׳קאאוט |

בתוך רצועה משתמשים ב**כלי הצבע הסמנטיים** במקום בצבע מפורש:

| utility | מה זה |
| --- | --- |
| `text-fg` | טקסט ראשי |
| `text-fg2` | טקסט משני |
| `text-fg3` | טקסט עדין / כיתובים |
| `text-accent` | הזהב, בגוון שעובר AA על הקרקע הנוכחית |
| `border-line` / `border-line-strong` | קווי הפרדה |
| `panel` | כרטיס — נייר עם קו שיער על בהיר, זכוכית טורקיז על כהה |

כך אותו כרטיס עובר מרצועה בהירה לכהה בלי לגעת ב-className שלו.

**למה זה חשוב לנגישות:** הזהב המותגי נותן 1.95:1 על שנהב — הוא קישוט בלבד
על קרקע בהירה ולא יכול לשאת טקסט לעולם. לטקסט קטן על בהיר יש
`--color-gold-ink` (5.07:1), שהוא אותו גוון שהורד בבהירות עד שעבר AA.
`text-accent` בוחר ביניהם לבד לפי הרצועה.

**הפלטה מאומתת.** הערכים ב-`globals.css` נדגמו פיקסל-אחר-פיקסל מדף הצבעים
הרשמי („רחלי צבעים”), לא באומדן מהלוגו. עשר המשבצות שם הן מקור האמת, וכל
טוקן מסומן בהערה לאיזו משבצת הוא שייך. הערכים שנגזרו ולא נדגמו (`ink`,
`void`, `night`) ושני הערכים שחושבו לניגודיות מסומנים ככאלה.

### טיפוגרפיה

**כל האתר ב-Rubik.** נטען כפונט משתנה (variable) ולא כשבעה חיתוכים
נפרדים: ציר ה-`wght` רץ ברצף מ-300 עד 900, כך שכל משקל שהעיצוב משתמש בו —
וכל ערך שביניהם — יוצא מקובץ אחד.

יש שני טוקנים, `--font-sans` ו-`--font-display`, ושניהם מצביעים היום על
Rubik. ההפרדה נשמרה בכוונה כדי שאפשר יהיה להחליף את הכותרות לפונט אחר
בשורה אחת. ההבדל בין כותרת לגוף טקסט נשען על **משקל וגודל** בלבד —
300 לשורות הקלות בהירו, 900 לכותרות.

שתי הערות שנובעות מהמעבר לרוביק:

- **בלי `tracking-tight`.** רוביק רחב יותר מסריף באותו גודל, ולעברית אין
  מה להרוויח מריווח שלילי שמתאים לטיפוגרפיה לטינית — הוא רק מצפיף את
  האותיות. סולם הכותרות נקבע בלי ריווח ובגודל קטן במקצת.
- **אין פונט כתב יד.** הרפרנס העיצובי משתמש בסריף נטוי לשורות ה„אמירה
  בצד”, ולעברית אין נטוי. פונטי הכתב-יד שמכסים עברית ב-Google Fonts בנויים
  ללימוד כתיבה ונראים כמו טעות. התפקיד הזה מתמלא ב-`ScriptLine` — רוביק
  במשקל הקל ביותר, מעל קו עט מצויר.

תמונת השיתוף משתמשת ב-`src/app/_assets/rubik-800.ttf` כדי שהיא תיראה כמו
האתר. אם מחליפים את פונט האתר — להחליף גם את הקובץ הזה.

### אלמנטים אדיטוריאליים

הכל ב-`src/components/ui/Editorial.tsx`:

| רכיב | מה זה |
| --- | --- |
| `ScriptLine` | שורת אמירה קצרה עם קו עט מתחת. שורה אחת, תמיד |
| `GhostBand` | הוורדמארק הענק שפותח פרק — קישוט, מוסתר מקוראי מסך |
| `Seal` | החותמת המסתובבת מעל הפורטרט |
| `CircleMark` | עיגול בעט סביב מילה בכותרת |
| `DoodleArrow` | חץ מצויר ביד |
| `pill` | הכפתורים: `solid` (טורקיז), `gold`, `coral`, `ghost` |
| `Photo` | תמונה, או מציין מקום ממותג עד שהקובץ מגיע |

**שתי מלכודות RTL שכבר נפלנו בהן — לא לחזור עליהן:**

1. ב-`Seal`, ל-`<text>` יש `direction: ltr` מפורש. מסמך RTL גורם ל-textPath
   להיפרס **אחורה** מנקודת ההתחלה, והטקסט מתכווץ לתו אחד. ה-LTR קובע רק את
   כיוון ההתקדמות על המסלול — העברית עצמה עדיין נפרסת נכון.
2. מזהה ה-`href` של ה-textPath חייב להיות ASCII. מזהה בעברית לא נפתר
   באופן עקבי, וגם אז ה-textPath מתכווץ בשקט.

## תמונות

העיצוב מוביל בצילום. `src/data/media.ts` מרכז את כל התמונות, וכולן מחוברות.
הקבצים ב-`public/photos/`, כולם WebP, יחד 288KB.

| slot | הקובץ | הצילום |
| --- | --- | --- |
| `hero` | `racheli-hero.webp` | פורטרט סטודיו, תאורת זהב על רקע כהה |
| `quote` | `racheli-stage.webp` | על הבמה מול אולם מלא |
| `story` | `racheli-story.webp` | חתוך מרקע, ז׳קט קורל |
| `podcast` | `racheli-speaking.webp` | מיקרופון ראש, באמצע הרצאה |

להחלפת תמונה: שומרים קובץ ב-`public/photos/` ומעדכנים `src`. שום דבר אחר
לא זז. `Photo` מקבל `fit="contain"` לתמונות חתוכות — `cover` היה חותך ראש.

### שתי מלכודות בחומרי המקור

**„קבצים חתוכים” שאינם חתוכים.** `תמונה רחלי22.png` נראה כאילו יש לו רקע
שקוף, אבל משבצות השחמט צבועות בפיקסלים — הקובץ RGB בלי ערוץ אלפא בכלל.
הוסר עם flood fill מהשוליים פנימה, כך שרק רקע שמחובר לקצה נמחק והחולצה
הלבנה שבמרכז הפריים לא נגעה. אם מגיע עוד קובץ „ללא רקע” — לבדוק
`hasAlpha` לפני שסומכים עליו.

**תמונות משפחתיות.** בתיקיית המקור יש כמה, וכולן הושארו בחוץ בכוונה. ה-
CLAUDE.md אוסר לפרסם תמונות שרואים בהן פני ילדים ללא אישור מפורש של רחלי.
שמות הקבצים לא מעידים — שתיים מהן נקראות „WhatsApp Image…”. **לבדוק כל
תמונה בעין לפני שמשבצים אותה.**

--- | --- |
| `hero` | פורטרט ראשי, רקע נקי, מבט למצלמה |
| `quote` | רחלי על הבמה מול קהל, לרוחב |
| `story` | פורטרט יושבת, אווירה חמה |
| `podcast` | רחלי עם מיקרופון בהקלטה |

**לחיבור תמונה:** שומרים את הקובץ תחת `public/photos/` ומעדכנים את `src`
ב-`media.ts`. שום דבר אחר לא משתנה.

אין תמונות סטוק בכוונה — מציין מקום שנראה כמו מציין מקום הוא כנה, ובעיקר
בלתי אפשרי לשלוח לאוויר בטעות.

**מגבלה מ-CLAUDE.md:** מותר להשתמש בצילומים מקצועיים של רחלי. אסור לפרסם
תמונות משפחתיות שרואים בהן פני ילדים ללא אישור מפורש שלה — ולכן אף slot כאן
לא מבקש כזו.

## עיצוב: אמנות הכיסוי של המוצרים

אין תמונות של המוצרים, ותמונות סטוק היו נראות כמו מילוי מקום. במקום זאת כל
מוצר מקבל „סיגיל” מצויר ב-`ProductSigil.tsx` — מוטיב לפי קטגוריה, שמשתנה
דטרמיניסטית לפי ה-slug:

| קטגוריה | מוטיב |
| --- | --- |
| תוכניות עסקיות | עמודות עולות — צמיחה וסקייל |
| שפע ומיינדסט | מעגלים מתפשטים — עבודה פנימית שמתפשטת חוצה |
| מועדון עסקים | עיגולים משתלבים — הקהילה |
| ספרים ומדריכים | דפים נפרשים |

הכל דטרמיניסטי בכוונה: אותו מוצר מקבל אותו ציור בכל build, בשרת ובדפדפן,
כך שאין הבדל בין הרינדור בצד השרת לצד הלקוח.

## תמונת השיתוף (OG) וטקסט עברי

`src/app/opengraph-image.tsx` מייצר את תמונת השיתוף לרשתות. שני דברים שם
נראים מוזרים אבל הכרחיים:

1. **הפונט נקרא מהריפו** (`src/app/_assets/rubik-800.ttf`) ולא מגוגל.
   fetch חי שם היה גורם לתצוגות המקדימות להישבר בשקט בכל תקלת רשת.
2. **כל טקסט עברי עובר דרך `visual()`** מ-`src/lib/bidi.ts`. המנוע שמרנדר
   את התמונה (Satori) לא מיישם את אלגוריתם ה-bidi של יוניקוד, ובלי הסידור
   הזה העברית יוצאת הפוכה. השורות מפוצלות ביד ומסומנות `nowrap` — גלישה
   אוטומטית של טקסט שכבר סודר חזותית תשבור את סדר הקריאה.

`src/lib/bidi.ts` הוא **רק לתמונות**. אסור להשתמש בו ב-HTML — דפדפנים
מיישמים bidi נכון, וטקסט הפוך שם ישבור בחירה, חיפוש וקוראי מסך.

## נגישות וביצועים

- כיוון `rtl` ושפה `he` ברמת המסמך, טיפוגרפיה עברית (Rubik, פונט משתנה 300–900).
- ניווט מלא במקלדת עם סימון מיקוד גלוי, דילוג לתוכן, ותוויות ARIA בעברית.
- `prefers-reduced-motion` מכבה את כל האנימציות **ואת הסצנה התלת-ממדית**,
  ובמקומה מוצג רקע סטטי.
- הסצנה נטענת ב-`dynamic import` ללא SSR, יורדת לאיכות נמוכה במובייל ובמכשירים
  חלשים, ולא נטענת כלל ללא WebGL.
- כל הגופים בסצנה מרונדרים ב-instancing — הסצנה כולה היא מספר קטן של draw calls.
