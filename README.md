# רחלי חדד — אתר ראשי + חנות

אתר תדמית וחנות איקומרס לרחלי חדד, מנטורית לעסקים וכסף.
Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4, ו-Three.js
לאנימציית ההירו התלת-ממדית. סליקה דרך **קארדקום**.

---

## הפעלה מקומית

```bash
npm install
cp .env.example .env.local   # ומלאו את הערכים
npm run dev                  # http://localhost:3000
```

בנייה לפרודקשן:

```bash
npm run build && npm start
```

## משתני סביבה

| משתנה | תיאור |
| --- | --- |
| `CARDCOM_TERMINAL` | מספר המסוף מהמערכת של קארדקום |
| `CARDCOM_API_NAME` | שם משתמש ה-API מקארדקום |
| `NEXT_PUBLIC_SITE_URL` | הכתובת הציבורית של האתר (חייבת להתאים לדומיין החי) |

את הערכים האמיתיים מגדירים בשרת/בפאנל האחסון — **לא** בקוד ולא ב-git.
ללא הגדרתם האתר עולה כרגיל, ורק כפתור התשלום מחזיר שגיאה מנומסת.

### עריכת תוכן

כל הטקסטים והמחירים יושבים ב-`src/data/`. לשינוי מחיר, שם תוכנית או
טקסט בעמוד הבית — עורכים שם בלבד, בלי לגעת ברכיבים.

### שלושת מצבי המוצר

לכל מוצר ב-`products.ts` יש `mode` שקובע איך רוכשים אותו:

| mode | התנהגות |
| --- | --- |
| `purchase` | יש מחיר מפורסם — נכנס לעגלה ועובר לסליקת קארדקום |
| `application` | ליווי במחיר לא מפורסם — הכפתור מוביל לשיחת התאמה, לא לעגלה |
| `free` | מדריך או הדרכה חינמית — הרשמה בלבד, לעולם לא נכנס לעגלה |

כרגע כל תוכניות הליווי הגדולות מוגדרות `application`, כי לא פורסם להן מחיר.
**כדי להפוך תוכנית למכירה ישירה** מוסיפים לה `price` ומשנים את ה-`mode`
ל-`purchase` — שאר האתר מתעדכן לבד. גם השרת אוכף את זה: ניסיון לשלוח מוצר
שאינו `purchase` לסליקה נדחה.

## תהליך התשלום

1. הלקוחה מוסיפה מוצרים לעגלה (נשמרת ב-`localStorage`).
2. בטופס התשלום נשלחים לשרת רק **מזהי המוצרים והכמויות**.
3. השרת מתמחר מחדש כל שורה מהקטלוג — **סכום שנשלח מהדפדפן לא נלקח בחשבון**,
   כך שלא ניתן לשנות מחיר מצד הלקוח.
4. השרת פותח עסקת LowProfile מול קארדקום ומחזיר כתובת לעמוד הסליקה.
5. קארדקום מחזירה את הלקוחה ל-`/checkout/success` או `/checkout/failed`,
   ובמקביל קוראת לשרת ל-`/api/cardcom/webhook`.
6. ה-webhook **מאמת מול קארדקום** את מצב העסקה לפני שהוא מסמן אותה כשולמה,
   כך שקריאה מזויפת לא יכולה לאשר הזמנה.

### מה נשאר לחבר לפני עלייה לאוויר

- [ ] להזין `CARDCOM_TERMINAL` ו-`CARDCOM_API_NAME` בשרת.
- [ ] להשלים את `fulfilOrder` ב-`src/app/api/cardcom/webhook/route.ts` —
      מתן גישה לתכנים, הוספה ל-CRM/דיוור ושליחת מייל פתיחה.
- [ ] **להחליף את פרטי הקשר** ב-`src/data/site.ts` — הטלפון, מספר הוואטסאפ
      וכתובות הרשתות החברתיות הם כרגע ערכי מקום ולא מספרים אמיתיים.
- [ ] להחליט אם לפרסם מחירים לתוכניות הליווי (ראו „שלושת מצבי המוצר”).
- [ ] להעביר את שלושת מסמכי ה-`legal` לעריכת עורך דין — הנוסח הנוכחי טיוטה.
- [ ] לוודא ששמות המשתתפות בהמלצות מאושרים לפרסום.
- [ ] להתקין את סקריפט „נגיש בקליק” — הצהרת הנגישות בפוטר כבר מפנה אליו,
      אבל הסקריפט עצמו עוד לא מוטמע ב-`layout.tsx`.
- [ ] להוסיף קישור ישיר לעמוד הספר באמזון (מוזכר בטקסט, אין עדיין URL).
- [ ] **פרטי משפחה** — שמות בן הזוג והילדים הוסרו במכוון מכל הטקסטים
      (במסמך המקור התערבבו שמות שאינם של רחלי). מספר הילדים גם הוא לא
      מצוין. להוסיף רק אם רחלי מאשרת במפורש מה לפרסם.

## נגישות וביצועים

- כיוון `rtl` ושפה `he` ברמת המסמך, טיפוגרפיה עברית (Heebo + Frank Ruhl Libre).
- ניווט מלא במקלדת עם סימון מיקוד גלוי, דילוג לתוכן, ותוויות ARIA בעברית.
- `prefers-reduced-motion` מכבה את כל האנימציות **ואת הסצנה התלת-ממדית**,
  ובמקומה מוצג רקע סטטי.
- הסצנה נטענת ב-`dynamic import` ללא SSR, יורדת לאיכות נמוכה במובייל ובמכשירים
  חלשים, ולא נטענת כלל ללא WebGL.
- כל הגופים בסצנה מרונדרים ב-instancing — הסצנה כולה היא מספר קטן של draw calls.
