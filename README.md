# רחלי חדד — אתר ראשי + חנות

אתר תדמית וחנות איקומרס לרחלי חדד, מנטורית לעסקים וכסף.
Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4, ו-Three.js
לאנימציית ההירו התלת-ממדית. סליקה דרך **קארדקום**.

---

## הפעלה מקומית

```bash
npm install
cp .env.example .env.local   # ומלאו את הערכים
npm run dev                  # http://localhost:3000
```

בנייה לפרודקשן:

```bash
npm run build && npm start
```

## משתני סביבה

| משתנה | תיאור |
| --- | --- |
| `CARDCOM_TERMINAL` | מספר המסוף מהמערכת של קארדקום |
| `CARDCOM_API_NAME` | שם משתמש ה-API מקארדקום |
| `NEXT_PUBLIC_SITE_URL` | הכתובת הציבורית של האתר (חייבת להתאים לדומיין החי) |
| `LEADS_WEBHOOK_URL` | יעד ההרשמות מ-`/api/register` — ווב-הוק של Make/Zapier/CRM |

את הערכים האמיתיים מגדירים בשרת/בפאנל האחסון — **לא** בקוד ולא ב-git.
ללא הגדרתם האתר עולה כרגיל, ורק כפתור התשלום מחזיר שגיאה מנומסת.

### עריכת תוכן

כל הטקסטים והמחירים יושבים ב-`src/data/`. לשינוי מחיר, שם תוכנית או
טקסט בעמוד הבית — עורכים שם בלבד, בלי לגעת ברכיבים.

### דפי נחיתה

`/partnerships` הוא דף נחיתה עצמאי לקמפיין — הדרכה חינמית בנושא קשרים
עסקיים ושת״פים. בשונה משאר האתר הוא **לא** מציג את התפריט והפוטר של האתר:
לדף נחיתה יש הצעה אחת, וניווט לידה הוא רק אוסף של יציאות. במקום זה יש בו
לוגו למעלה וקישורי חובה (תקנון, פרטיות, נגישות) למטה.

מי שמסתיר את התפריט הוא `ChromeGate` ב-`src/components/ui/ChromeGate.tsx` —
רשימת נתיבים שבהם ה-`Header` וה-`Footer` לא נטענים. דף נחיתה חדש מתווסף שם.

**רקע בהיר.** בשונה משאר האתר הדף רץ על רקע שנהב חם ולא על הטורקיז-שחור.
אותם שני גוונים של המותג, בהיפוך תפקידים: הטורקיז הוא הדיו והזהב נשאר
המבטא. הערכים יושבים ב-`@theme` ב-`globals.css` (`ivory`, `sand`, `shell`,
`ink`, `ink-soft`, `gold-ink`, `coral-ink`) — **תוספת בלבד, הפלטה הכהה לא
השתנתה.** לזהב יש שני ערכים בכוונה: `gold` לכותרות גדולות, ו-`gold-ink`
הכהה יותר לכל טקסט קטן, כי הזהב התצוגתי מגיע רק ל-3:1 על שנהב.

שתי מלכודות שכדאי להכיר לפני שמוסיפים דף נחיתה בהיר:

- העטיפה של הדף צובעת רקע, ולכן שכבה עם `-z-10` נעלמת מתחתיו. כל אלמנט
  שמארח שכבה כזאת צריך `isolate`.
- ל-`:root` יש `color-scheme: dark`, אז בלי `surface-light` על העטיפה
  הדפדפן מצייר שדות טופס, מילוי אוטומטי וסרגלי גלילה כהים על דף בהיר.

כל הטקסטים של הדף יושבים ב-`src/data/partnerships.ts`.

**תאריך ההדרכה:** השדות `event.date`, `event.time` ו-`event.platform` ריקים
בכוונה — אין לפרסם מועד או פלטפורמה שרחלי לא אישרה. ברגע שממלאים אותם הם
מופיעים לבד בהירו ומעל טופס ההרשמה; מה שנשאר ריק פשוט לא מוצג.

**ההרשמות** נשלחות ל-`/api/register`, שמאמת את הפרטים ומעביר אותם ל-
`LEADS_WEBHOOK_URL`. **בלי המשתנה הזה ההרשמה נרשמת רק ללוג של השרת** —
חובה להגדיר אותו לפני שהקמפיין עולה.

### הדף בפיגמה

`figma-plugin/` הוא תוסף מקומי שבונה את דף הנחיתה בתוך פיגמה — טוקנים,
סגנונות טקסט, קומפוננטות, דסקטופ, מובייל ומצב ההצלחה של הטופס. הוא קיים כי
לשרת ה-MCP של פיגמה יש מכסה לפי תוכנית (20 קריאות בחודש ב-Starter), ובניית
דף שלם דורשת הרבה יותר; תוסף מקומי משתמש באותו Plugin API בלי מכסה.

הטקסטים נשאבים מ-`src/data/` בזמן בנייה ולא משוכפלים בתוסף. אחרי שינוי תוכן:
`node figma-plugin/build.mjs`, ואז להריץ שוב את התוסף. ההוראות המלאות
ב-`figma-plugin/README.md`.

### שלושת מצבי המוצר

לכל מוצר ב-`products.ts` יש `mode` שקובע איך רוכשים אותו:

| mode | התנהגות |
| --- | --- |
| `purchase` | יש מחיר מפורסם — נכנס לעגלה ועובר לסליקת קארדקום |
| `application` | ליווי במחיר לא מפורסם — הכפתור מוביל לשיחת התאמה, לא לעגלה |
| `free` | מדריך או הדרכה חינמית — הרשמה בלבד, לעולם לא נכנס לעגלה |

כרגע כל תוכניות הליווי הגדולות מוגדרות `application`, כי לא פורסם להן מחיר.
**כדי להפוך תוכנית למכירה ישירה** מוסיפים לה `price` ומשנים את ה-`mode`
ל-`purchase` — שאר האתר מתעדכן לבד. גם השרת אוכף את זה: ניסיון לשלוח מוצר
שאינו `purchase` לסליקה נדחה.

## תהליך התשלום

1. הלקוחה מוסיפה מוצרים לעגלה (נשמרת ב-`localStorage`).
2. בטופס התשלום נשלחים לשרת רק **מזהי המוצרים והכמויות**.
3. השרת מתמחר מחדש כל שורה מהקטלוג — **סכום שנשלח מהדפדפן לא נלקח בחשבון**,
   כך שלא ניתן לשנות מחיר מצד הלקוח.
4. השרת פותח עסקת LowProfile מול קארדקום ומחזיר כתובת לעמוד הסליקה.
5. קארדקום מחזירה את הלקוחה ל-`/checkout/success` או `/checkout/failed`,
   ובמקביל קוראת לשרת ל-`/api/cardcom/webhook`.
6. ה-webhook **מאמת מול קארדקום** את מצב העסקה לפני שהוא מסמן אותה כשולמה,
   כך שקריאה מזויפת לא יכולה לאשר הזמנה.

      מצוין. להוסיף רק אם רחלי מאשרת במפורש מה לפרסם.

## עיצוב: אמנות הכיסוי של המוצרים

אין תמונות של המוצרים, ותמונות סטוק היו נראות כמו מילוי מקום. במקום זאת כל
מוצר מקבל „סיגיל” מצויר ב-`ProductSigil.tsx` — מוטיב לפי קטגוריה, שמשתנה
דטרמיניסטית לפי ה-slug:

| קטגוריה | מוטיב |
| --- | --- |
| תוכניות עסקיות | עמודות עולות — צמיחה וסקייל |
| שפע ומיינדסט | מעגלים מתפשטים — עבודה פנימית שמתפשטת חוצה |
| מועדון עסקים | עיגולים משתלבים — הקהילה |
| ספרים ומדריכים | דפים נפרשים |

הכל דטרמיניסטי בכוונה: אותו מוצר מקבל אותו ציור בכל build, בשרת ובדפדפן,
כך שאין הבדל בין הרינדור בצד השרת לצד הלקוח.

## תמונת השיתוף (OG) וטקסט עברי

`src/app/opengraph-image.tsx` מייצר את תמונת השיתוף לרשתות. שני דברים שם
נראים מוזרים אבל הכרחיים:

1. **הפונט נקרא מהריפו** (`src/app/_assets/heebo-800.ttf`) ולא מגוגל.
   fetch חי שם היה גורם לתצוגות המקדימות להישבר בשקט בכל תקלת רשת.
2. **כל טקסט עברי עובר דרך `visual()`** מ-`src/lib/bidi.ts`. המנוע שמרנדר
   את התמונה (Satori) לא מיישם את אלגוריתם ה-bidi של יוניקוד, ובלי הסידור
   הזה העברית יוצאת הפוכה. השורות מפוצלות ביד ומסומנות `nowrap` — גלישה
   אוטומטית של טקסט שכבר סודר חזותית תשבור את סדר הקריאה.

`src/lib/bidi.ts` הוא **רק לתמונות**. אסור להשתמש בו ב-HTML — דפדפנים
מיישמים bidi נכון, וטקסט הפוך שם ישבור בחירה, חיפוש וקוראי מסך.

## נגישות וביצועים

- כיוון `rtl` ושפה `he` ברמת המסמך, טיפוגרפיה עברית (Heebo + Frank Ruhl Libre).
- ניווט מלא במקלדת עם סימון מיקוד גלוי, דילוג לתוכן, ותוויות ARIA בעברית.
- `prefers-reduced-motion` מכבה את כל האנימציות **ואת הסצנה התלת-ממדית**,
  ובמקומה מוצג רקע סטטי.
- הסצנה נטענת ב-`dynamic import` ללא SSR, יורדת לאיכות נמוכה במובייל ובמכשירים
  חלשים, ולא נטענת כלל ללא WebGL.
- כל הגופים בסצנה מרונדרים ב-instancing — הסצנה כולה היא מספר קטן של draw calls.
